# Accuracy under increasing archived conversation length

## Material Passport
- Mode: authorized code experiment and reviewer-response revision.
- Data: five simulated patient profiles; no human participants or clinical outcomes.
- Source: completed `../memory-comparison-run-2026-09-29`, first repetition, structured arm, sessions 1–9 only.
- Status: freeze this protocol, code, inputs and scoring rubric before the first API call.

## Question and scope
Can the existing evidence-memory retriever supply old conversation facts when an
increasing amount of unrelated dialogue has been appended, compared with sending
the entire same archive to Gemini 2.5 Pro? This is an exploratory **retrieval
component stress test**, not an extension of the complete 11-session graph run.
The shared starting transcripts were generated by the structured arm. No primary
recall-probe answers from sessions 10–11 enter either condition.

Five profiles × five lengths × two conditions = 50 planned patient calls. One
call per cell, with all six original questions numbered in a single prompt.
This batching differs from the original single-question endpoint and may impose
a coverage bottleneck on eight-item retrieval. It is reported explicitly.

## Inputs and conditions
1. **Full history**: all original and added therapist/patient turns, in order,
   without truncation, compression, summarization, or retrieval.
2. **Evidence memory**: unchanged native `EvidenceMemory.retrieve`, limit eight
   items and 1,800 estimated-token evidence budget, over the same complete raw
   archive and the original automatically extracted fact batches from sessions
   1–9. Batch sources must belong entirely to that prefix. Added synthetic
   dialogue remains in the raw store and is searchable; it is **not consolidated
   into new facts**. No summaries, reflections, recent-history window, emotional
   graph state, or newly extracted facts are added. This isolates a memory
   component and does not measure the complete system at large scale.

The full common CASE and instructions are identical. No expected answers are
supplied to generation or retrieval. The fixed query is the concatenation of the
six questions, without gold values. Both arms must answer six numbered sections.
The retriever uses cached all-MiniLM-L6-v2 revision
`1110a243fdf4706b3f48f1d95db1a4f5529b4d41`, CPU, unchanged lexical/semantic scoring.
Query truncation by the encoder is measured and reported. The lexical scorer
still sees the complete query. All selected evidence is archived.
The local SciPy overlay is restored in a separate temporary directory at the
same recorded version 1.16.3; no original dependency directory is modified.

Nested dialogue prefixes target approximately: base, 64,000, 256,000, 900,000,
and 1,200,000 **full-prompt text tokens**, measured with Google's experimental
local Gemini tokenizer (`google-genai` 2.25.0). Provider-reported counts are the
authority for accepted requests; local counts are separately labeled. Synthetic
filler consists of deterministic varied communication-practice exchanges, with
fixed seed 20260930. It introduces no target names, times, updates, or surname.
Targets remain near the start and grow farther from the query. This does not test
all information positions, clinical realism of long histories, or arbitrary
numbers of salient facts. Similar easy filler can favor retrieval.

## Model, service and execution
- OpenRouter only: `google/gemini-2.5-pro`; native response must attest this ID.
- Patient temperature 0.7; top-p 0.95; maximum output 4,096 tokens, including a
  requested reasoning budget of 1,024. Existing stop sequences preserved.
- No API seed; top-k 40 remains omitted from the wire as in the comparison.
- Provider requires supported parameters; no fallback. No context-compression
  plugin or transform requested. Complete wire requests are archived.
- Same existing transport, in-band error handling and proven timeout/rate-limit
  retry policy, at most three total attempts; at least five seconds between
  request starts. A single output-budget retry to 8,192 is allowed only for an
  explicit `length` finish, never for answer accuracy.
- HTTP timeout 300 seconds to allow large inputs. The original runner's local
  64,000-token estimate cap is not used in this separate harness. Original files
  and experiments remain immutable.
- Lengths ascending; profile and within-pair arm order randomized with seed
  20260930 before execution. No automatic experiment restart.
- A clearly archived HTTP/API 400 context-length rejection on a locally
  over-limit full-history input is an expected availability outcome; preserve it
  and continue. Any other unresolved provider/protocol error stops collection.
- Local budget stopping rule: before each logical call, observed charges plus
  conservative reserves for unpriced timeout attempts and the next call's
  possible retry attempts must remain below USD 40. Forecast input at USD 4.50/M
  and output at USD 27/M with 10% margin, using the archived endpoint catalogue.
  This is an execution cap, not a claim that a provider cannot change prices.

## Endpoints and analysis fixed before collection
Primary semantic endpoint: number of fully correct categories / six categories
for every technically complete response (30 per arm/length when all five calls
return). An omitted section or field is an error, never removed from that
denominator. Correct explicit abstention on the absent surname
counts as correct. Partial, incorrect, contradictory, uncertain, and inappropriate
abstention are not full passes. Identity, notebook, four appointment fields,
two venue fields, two activity fields, and absent surname follow the archived
gold/rubric. Preserve relationship/status, not mere keyword occurrence.

Report separately: complete responses / five attempted, context rejections,
other errors, strict category accuracy, all-six profile success, correct fields
/60 where evaluable, and per-category/profile results. An over-limit rejection
has **no semantic score**, never a fictitious 0% recall score. Do not combine it
with model mistakes. Report achieved prompt tokens, retrieval size, timing and
cost. Five profiles are the independent case units; categories and nested
lengths are correlated. Descriptive estimates only, no significance tests or
independent-binomial confidence intervals.

Two fresh automatic raters receive randomly labeled raw answers and gold,
without arm, length, source prompts or peer ratings. Record requested model and
runtime identity limitations; these are not human clinical ratings. Resolve
disagreements using a fresh adjudicator. Freeze exports before review. No
accuracy-directed retries, changed filler, tuning retrieval, or dropped cells.

## Reproducibility and reporting
Archive source hashes, corpus prefixes, copied memory, exact prompts, native
requests/responses, schedule, local token counts, selected evidence, ratings,
per-cell metrics, costs, and a final hash manifest. Keep original longitudinal
results (85/90 structured, 89/90 full history) distinct from this batched stress
test. A rejection demonstrates a finite input limit; retention depends on the
measured performance of retrieval, not merely on having external storage.
